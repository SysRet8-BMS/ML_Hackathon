# Initial dataset audit

Generated by `python data_processing/eda.py` from `Datasets/train` and
`Datasets/student_test` only. No evaluator trip contents were read. Counts below
are descriptive checks, not model results.

| Partition | Trips | GPS rows (min / median / max) | Route arcs (min / median / max) | GPS rows / route arcs (range) |
|---|---:|---:|---:|---:|
| Train | 80 | 361 / 1,529 / 19,313 | 59 / 280 / 2,266 | 1.26–56.98 |
| Student test | 10 | 262 / 1,420 / 3,958 | 95 / 250 / 1,323 | 2.45–14.59 |

All 90 examined trips had four expected files. GPS rows parsed as valid coordinates,
timestamps were strictly increasing, and every arc endpoint index was within the
node array. The training trips have a median of 15.5 timestamp steps over one
second (maximum 1,268); student-test median is 1 (maximum 206). These are counts
per trip and warrant explicit gap handling. Networks have no isolated nodes in
the examined files, but connected component counts vary considerably (train
median 20, maximum 421; student-test median 11, maximum 100). These counts use
an undirected graph for exploration and include isolates in the component total.
Every route arc ID is in range. A strict directed endpoint check finds 13
consecutive-arc discontinuities across 10 training trips and 1 across the
student-test trips. This is a diagnostic requiring inspection: route arc
orientation, route encoding, and possible reference imperfections should be
checked before treating this count as an error or using route continuity as a
label-quality guarantee.

The GPS coordinate extents span multiple widely separated regions (overall
longitude -100.42 to 137.24 and latitude -34.64 to 61.70). A single fixed UTM
zone is therefore not suitable for all trips; choose a local projection per trip
or use geodesic distances. These extents are across trips, not a single journey.

Track and route lengths differ materially, so row-wise alignment is invalid.
The ratio alone does not establish a point-to-arc labeling rule. Before training,
implement and inspect a chronological alignment strategy, validate arc IDs and
route continuity, and report ambiguous labels and candidate misses. The supplied
route is a reference with documented limitations, not assumed perfect truth.

- `partition_summary.csv`: aggregate counts.
